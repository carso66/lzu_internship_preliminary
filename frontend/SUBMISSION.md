## 启动方式（必填，要能照抄）

评审检出 PR 对应的学号分支 `220260948730` 后，在**仓库根目录**打开两个 Windows PowerShell 窗口。运行环境见上方表格。

### 1. 第一个窗口启动 Mock

```powershell
node .\frontend\mock\server.mjs
```

看到「好物市集 mock 已启动」后保持这个窗口开着。在浏览器打开 `http://127.0.0.1:3001/api/products`，应看到商品 JSON。Mock 使用题目自带的初始数据。

### 2. 第二个窗口安装依赖并启动前端

```powershell
Set-Location .\frontend
npm.cmd ci
npm.cmd run dev
```

`npm.cmd ci` 按仓库里的 `package-lock.json` 安装依赖。看到 Vite 打印的 `Local` 地址后，保持这个窗口开着。

### 3. 打开页面并复现基本流程

用浏览器打开 Vite 的 `Local` 地址，通常是 `http://localhost:5173/`。如果终端显示了其他端口，使用终端显示的地址。

1. 首页是「商品管理」。确认能看到商品列表，发布一件测试商品，再试一次下架和上架。
2. 点顶部「商品选购」进入 `/shop.html`。选一件有库存的在售商品，输入数量并下单。确认库存减少，订单列表出现新的「待支付」订单。
3. 对这笔订单点「去支付」，选支付宝或微信，再点「开始模拟支付」。等待页面提示成功，确认订单更新为「已支付」。

要恢复干净的初始状态，在第一个窗口按 `Ctrl+C` 停掉 Mock，再重新运行第 1 步。重启会清除本轮创建的商品、订单和支付记录。

### HTTP 响应实测

HTTP 状态在 Network 的 Status 列查看，业务码和返回字段在 Response 中查看。

| 场景 | 请求 | HTTP | 业务码 `code` | 实测结果 |
|---|---|---:|---:|---|
| 查询全部商品 | `GET /api/products?page=1&pageSize=50` | 200 | 0 | 初始 `data.total` 为 24，`data.items` 有 24 条。 |
| 搜索及分类 | `GET /api/products`，带 `keyword` 或 `category` | 200 | 0 | 「耳机」匹配多条，`zzz` 返回空数组，「图书」只返回该分类。 |
| 发布商品 | `POST /api/products` | 201 | 0 | 返回新商品，状态为 `on`，重新查询时新商品排在末尾。 |
| 上下架 | `PATCH /api/products/{id}/status` | 200 | 0 | 请求体分别发送 `status: "off"` 和 `status: "on"`，响应与请求一致。 |
| 正常下单 | `POST /api/orders` | 201 | 0 | 数量传数字 2，单价 4990 分，`totalAmount` 为 9980 分，库存减少 2。 |
| 购买数量超过库存 | `POST /api/orders` | 409 | 40901 | `message` 为「库存不足」。 |
| 对下架商品下单 | `POST /api/orders` | 409 | 40902 | `message` 为「商品已下架」。 |
| 查询订单 | `GET /api/orders` | 200 | 0 | 可找到刚创建的订单，支付后订单状态为 `paid`。 |
| 发起支付 | `POST /api/payments` | 200 | 0 | `alipay` 和 `wechat` 都可创建模拟支付单，返回 `paymentId` 和 `processing`。 |
| 轮询支付状态 | `GET /api/payments/{paymentId}` | 200 | 0 | 先返回 `processing`，随后返回 `paid`。前端根据 `data.status` 更新状态。 |
| 重复支付已支付订单 | `POST /api/payments` | 409 | 40903 | `message` 为「订单已支付，请勿重复支付」。 |

### 金额、表单及并发交互验证

| 检查项 | 结果 |
|---|---|
| 元转分 | 前端验证 `12 → 1200`、`19.9 → 1990`、`12.50 → 1250`、`0.01 → 1`。Mock 接收并原样返回这四个整数分值。 |
| 发布表单拦截 | 空标题、51 字标题、价格 `0`、`19.999`、库存 `-1`、`1000`、`1.5` 均显示字段提示，发出 0 次 `POST /api/products`。 |
| 下单数量拦截 | 数量 `0`、`-1` 和 `1.5` 均发出 0 次 `POST /api/orders`。 |
| 五次连续触发 | 模拟慢响应下只发出 1 次 `POST /api/orders`。等待期间按钮保留在原位、禁用并显示「提交中…」。模拟库存不足后，按钮恢复并可重试。 |
| 支付中间态 | 模拟状态查询返回 `processing` 时继续显示「支付中…」，收到 `paid` 后才显示成功。 |
| 轮询上限 | 模拟持续返回 `processing`，第 10 次查询后停止，提示「支付状态未确认，请稍后在订单列表查看」。 |
| 停止轮询 | 模拟关闭弹窗和离开页面，后续轮询定时器被清除。关闭时正在进行的状态请求会取消。 |
| 重复支付提示 | 模拟后端返回 `40903`，弹窗显示后端原文。订单已显示为「已支付」时，点击提示区域会弹出说明，发出 0 次新的支付 POST。 |
