## 3. 四个场景（5 分）

### 场景 1：L0-4 上下架 + L0-5 搜索框（成功，方案一次过）

- **我的原话**（平台日志可对）：「……现在帮我完成 L0-4 和 L0-5 要求的任务，L0-5 任务你在右上角发布商品按钮旁边加个搜索框，输入搜索内容后需要有他要求的这些内容和反馈。」
- **用的模型 / 为什么**：deepseek-v4.1-flash——提前说清楚一些设计细节，避免AI写完之后需要回滚。
- **它给了什么**：先给方案再动手——上下架用「进行中 id 集合 + 事件委托」，并指出按钮文案与徽标必须来自同一份映射；搜索框做 300ms 防抖 + 回车提交 + 一键清空，空态带「清空筛选」。
- **我改了吗**：位置和交互按我的要求定（搜索框在「+ 发布商品」左边、边打边搜）；请求留在 `main.js`、列表只负责渲染，这条边界也是我定的。另外让它成功后用**服务端返回的 status** 写回 state，而不是本地取反。
- **怎么确认**：单测覆盖 `toggleTarget / actionLabel`；再用临时 DOM 脚本连点 2 次，Network 里只有 1 个 PATCH；搜 `zzz` 出空态，点「清空筛选」后列表和搜索框一起复原。
- **结论**：直接用。

### 场景 2：L1 四个任务（按「严格照描述」实现，中途改了它的结构）

- **我的原话**：「现在实现 L1 的几个要求任务，严格按照描述实现。」
- **用的模型 / 为什么**：deepseek-v4.1-flash——一次要覆盖四个验收块（下单 / 订单 / 金额 / 校验），跨模块。
- **它给了什么**：订单表 + 购买弹窗（预估总价用整数分乘法）+ 金额工具 + 分层校验（校验不过不发请求）。加第二个弹窗时它主动指出：原来的 toast 挂在发布面板上，两个面板会各建一条叠在一起，于是抽 `toast.js`、由 `main.js` 注入 `notify`。
- **我改了吗**：采纳这次重构；「已支付订单能不能点支付」按验收条目倒推——直接禁用就测不到「对已支付订单 → 显示后端 message」，所以只有本会话付成功的才永久禁用。
- **它另外主动发现的一个坑**：标题输入框上原本有 `maxLength: 50`，超长会被浏览器**静默截断**，评审输入 51 字反而「提交成功」——L1-9 的「51 字被拦下」就永远测不到。我确认后去掉 `maxLength`，只留 `validateProductForm` 的校验（错误显示在字段下方、请求不发）。
- **怎么确认**：`npm test` 81 条全过；手工点：买 2 件后库存 50→48、新订单出现在列表、数量 0 不发请求、`19.999` 元 / 1000 库存 / 51 字标题都在字段下方报错。
- **结论**：改了之后用。

### 场景 3：L2-10 支付链路（异步状态机的取舍）

- **我的原话**：「现在帮我实现 L2-1 的支付链路任务。」
- **用的模型 / 为什么**：deepseek-v4.1-flash——轮询 + 清理是典型的异步状态机问题，快模型容易只给「能轮询」的版本。
- **它给了什么**：把轮询单独抽成 `payment-poller.js`（1 秒一次、最多 10 次、只认 `paid`、`stop()` 清定时器 + abort 在飞请求 + 丢弃晚到结果），面板只管 UI 与回调；另外补了 `pagehide`。
- **我改了吗**：有一处我要求改：它原来在「到上限」那次也会先回调 `onProcessing` 再 `onTimeout`，界面会闪一下「支付中（第 10 次）」再报错；我让上限判断提前，单测里「重试阶段只回调 2 次」的断言才成立。
- **我怎么验证的**：让它先列出「关闭组件时可能漏请求的路径」，它给了三条（只清定时器不够 / `await` 后没判停止 / 没有 `pagehide`），按三条补实现 + 一条单测「请求在飞时 stop，晚到的结果不写界面」；再跑临时 DOM 脚本量出：GET 间隔 1007 / 1000ms、processing 期间一直是「支付中」、paid 后行按钮「已支付」且禁用、一直 processing 时第 10 次后提示未确认、**轮询中关弹窗后 4.2 秒新增 GET 为 0**、对已支付订单点支付显示「订单已支付，请勿重复支付」。
- **结论**：用了，每条验收都有可复现的数字。

### 场景 4：提交前让它审查「换台机器能不能跑」（必答：用 AI 做验证）

- **我想干什么**：不只看「我这儿能跑」，还要确认考官 clone 之后能跑。
- **我的原话**：「检查一下 SUBMISSION.md 里面的启动方式正确吗，考官拿到我提交的分支代码后可以在他的电脑上运行起来吗……」
- **用的模型 / 为什么**：〔强模型〕——要它读文档、读配置、读 git 状态之后下判断，而不是重写一份文档。
- **它指出了什么**：① 分支里只提交到 L0-1：`src/publish-form.js`、`payment-*.js` 等 9 个模块和 7 个测试文件还没被跟踪，考官拿不到；② 环境表只写了我的 Node 版本，没写最低要求（Vite 5 要 Node ≥ 18）；③ 3001 / 5173 被占时没有兜底；④ 截图缺订单列表和支付流程。
- **我怎么验证的**：用只读的 `git status` / `git ls-files` 复核了①（确实只有 7 个 src 文件被跟踪）；按清单补了 `npm ci`、Node 版本、端口兜底和「30 秒自检」三条。
- **我改掉/没采纳它的什么**：它只提醒了「记得提交」，没给节奏；我自己定为三步提交（代码 / 文档 / 截图），保证每一步可回溯、第一个 commit 之后就能跑。
- **结论**：采纳。这次它没写业务代码，但避免了一个会直接掉分的坑。

## 4. 一次被 AI 带偏的经历（必答）

- **它给了什么**：L1 的金额工具，第一版是 `const total = Number(unit) * Number(qty)`，看起来天经地义。
- **当时为什么信了**：整数分相乘，简单到我没多想——也没想到「字段缺失」会一路走到这里。
- **你怎么发现的**：它写完后跑 `npm test`，报 `expected +0 to be null`：单价缺失时，购买弹窗的预估总价显示 `¥0.00` 而不是「—」。顺着断言查到 `Number(null) === 0`。
- **最后怎么修的**：在 `multiplyCents` 里先显式挡掉 `null / undefined / ''` 再转数字，并补两条用例（这两种输入必须抛错）；展示层继续用 `formatCnySafe` 兜底。
- **之后你改了做法吗**：改了。凡是金额、ID 这种「缺省值也有意义」的参数，先列边界（空、0、小数、超大）再写实现；并且**先有测试再让它写实现**，让失败自己冒出来，而不是靠我盯着代码看。
