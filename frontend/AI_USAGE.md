### 为什么没有使用作业平台完成开发

我能登录 XYtoken 控制台并创建 API Key，也能打开官方使用指南。按手册核对了 OpenAI 兼容的 Base URL，先尝试聊天接口，后来改用 `GET /v1/models` 验证连接和 Key 可用的模型。

1. **换过调用方式。** 我用 Git Bash 的 `curl`、PowerShell 的 `Invoke-RestMethod` 和 Node.js 的 `fetch` 测试。不同尝试遇到过域名无法解析、HTTPS 握手失败或连接被关闭。模型列表请求无需填写模型名，不带 Key 的连接测试也失败，这把排查范围缩小到了连接阶段。那些失败没有给出能核验 Key 或模型权限的 API 响应。
2. **换过网络并按老师要求做了 ping。** 我试过校园网、手机热点和开启代理。开代理时，`ping api.xytoken.com` 解析到 `198.18.0.7`，收到了 4 次回复。这个地址很可能是代理分配的虚拟 IP，所以 ping 的结果只能反映这次测试中该地址有回应，HTTPS 接口当时仍访问失败。
3. **按答疑建议继续试过接入。** 后来按老师的建议用 CC Switch 配置和测试，最终遇到权限提示，仍未拿到可用的模型回复。对这个权限提示的具体原因没有确认。我检查过控制台的模型调用日志，当时没有成功调用记录。

考虑到提交时间，我先继续开发，用自己的 ChatGPT/Codex 会话辅助。下文的提问、代码建议和验收都是个人会话或本地项目中的实际操作。

## 3. 挑 4 个场景写下来（5 分）

### 场景 1：用预览确定商品管理页布局

- **我想干什么**：商品多时，列表会拉得很长，发布表单和列表高低不齐。我想把商品列表放进一个能滚动的框里，再加分类导航。
- **用的工具 / 为什么选它**：用 ChatGPT/Codex 的图像生成工具先看效果。这样可以在动代码前判断三栏布局合不合适。
- **我怎么问的**：「列表和右边发布表单底部对齐，内容在框内滚动。左边加全部和五个分类，先给我预览图。」
- **它给了什么**：左侧分类、中间滚动列表、右侧发布表单的预览，并给了 HTML、CSS 和 JavaScript。
- **我改了吗、为什么改**：我确认采用这套布局，发布成功提示改成弹窗，因为表单下方的一行提示不够明显。
- **怎么确认改对了**：在 Vite 页面点分类、输关键词、滚到列表末尾，再发布测试商品，检查弹窗和新商品位置。
- **结论**：确认布局后采用，按实际操作调整反馈。

### 场景 2：排查 XYtoken 接入失败

- **我想干什么**：用自己的作业 Key 获得第一条模型回复。
- **用的工具 / 为什么选它**：用 ChatGPT/Codex 读报错并核对官方手册，便于区分终端语法、网络连接和平台响应。
- **我怎么问的**：「Git Bash 报 SSL/TLS 握手失败，PowerShell 也连接关闭。这个地址和模型名写对了吗？」
- **它给了什么**：核对 Base URL 后，建议改测模型列表和不带 Key 的连接请求，再用 DNS 查询、不同网络和代理作对照。
- **我改了吗、为什么改**：先照着测了几种连接方式。后来根据无密钥测试仍失败的结果，停止反复改模型名，转向网络和接入排查。
- **怎么确认的**：模型列表接口仍未返回成功响应，控制台没有成功调用记录。按答疑建议配置 CC Switch 后也未获得模型回复。
- **结论**：排查做了，但平台接入没有跑通。项目其余部分继续使用个人 AI 会话辅助。

### 场景 3：调整已支付订单的提示方式

- **我想干什么**：既满足已支付按钮禁用，又能让用户点击该区域看到「订单已支付，请勿重复支付」。
- **用的工具 / 为什么选它**：用 ChatGPT/Codex 比较按钮禁用、弹窗和接口报错如何同时处理。
- **我怎么问的**：「已支付状态的订单虽然按钮禁用，但是点击要弹信息。」
- **它给了什么**：已支付按钮保持禁用，外层操作区只打开提示弹窗。如果页面状态落后，发起支付后收到后端业务码 `40903`，用同一个弹窗显示后端原文。
- **我改了吗、为什么改**：我确定了要用独立弹窗，也要求先给方案、确认后再给完整文件。我自己把确认的版本复制到克隆仓库并提交。
- **怎么确认改对了**：手动点击「已支付」区域看弹窗。接口测试确认重复支付返回 HTTP `409`、业务码 `40903`，前端模拟响应检查了弹窗文案和按钮状态。
- **结论**：采用。已知已支付时只提示，服务器返回重复支付错误时显示其原文。

### 场景 4：我用 AI 验证防重复下单和金额换算

- **我想干什么**：确认快速连点只发一条下单请求，失败后可以重试，并让金额测试覆盖发布表单实际使用的函数。
- **用的工具 / 为什么选它**：用 ChatGPT/Codex 对照 README 检查代码，并运行可复核的测试。
- **我怎么问的**：「快速连点五次应该只有一次 POST，失败后还可以重试。现在的代码做到没有？把需要验证的响应列出来。」
- **它指出了什么**：现有下单逻辑在发送请求前已禁用按钮，也用提交状态拦住重复事件。订单列表刷新发的是 GET，统计连点结果时只数 `POST /api/orders`。它还建议把发布表单中的元转分函数单独导出，测试直接调用同一个函数。
- **我怎么验证的**：模拟慢请求下连续触发五次提交，只发出一次 POST。模拟库存不足后恢复了按钮，随后能重试。金额部分我自己在 PowerShell 执行 `npm.cmd test`，结果是 9 条通过、0 条失败，覆盖 5 个有效值和 4 个非法值。页面显示和操作另外手动点验。
- **结论**：用请求次数和测试输出判断是否通过。金额测试使用 Node.js 自带的运行器。

## 4. 一次被 AI 带偏的经历（必答）

- **它给了什么**：为了找 XYtoken 的实际地址，AI 一开始让我在控制台左侧找一个叫「API 接入」的菜单。
- **当时为什么信了**：使用指南也提到了这个名称，我以为登录后一定会看到单独入口。
- **怎么发现的**：我把控制台的完整菜单截给它看。左侧能看到 API Keys、My Call Logs 等栏目，但在我看到的界面里没有独立的「API 接入」菜单。
- **最后怎么修的**：从顶部使用指南核对 Base URL，并用不带 Key 的请求测试是否有 HTTP 响应。后来把接入现象和 ping 结果用于答疑。
- **之后改了什么**：我会先贴实际界面和报错，再让 AI 按可见内容定位。遇到方案或文件需要修改时，也先确认范围，再由我决定是否替换和提交。
