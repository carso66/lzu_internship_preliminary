| 顺序 | 我做的事 | 为什么排在这个位置 |
|---|---|---|
| 1 | 启动 Mock，在浏览器打开商品接口，看返回的JSON。 | 先确认服务能访问，并弄清商品数组在 `data.items`、价格以分为单位、上下架用 `on` 和 `off` 表示。 |
| 2 | 搭商品管理页，依次接商品列表、发布和上下架。 | 商品列表是后续操作的验收入口。先能从接口看到商品，才能判断发布后有没有新商品、上下架后状态有没有变化。 |

## 3. 我的程序分成哪几块

我以前用过 Dreamweaver 写网页，所以这次用它编辑原生 HTML、CSS 和 JavaScript。Vite 负责本地预览，业务数据由题目提供的 Mock 返回。

| 文件 / 模块 | 负责什么 | 为什么单独拆出来 |
|---|---|---|
| `index.html`、`src/main.js` | 商品管理。处理分类、搜索、列表、发布校验和上下架。 | 发布和上下架都直接影响商品列表，放在同一页方便操作后核对结果。 |
| `shop.html`、`src/shop.js` | 商品选购、预估金额、下单弹窗、订单记录和支付。 | 用户能在下单后留在同一页看库存变化和新订单，之后也能直接找到支付入口，不与发布商品的管理页混在一起，这样更方便使用 |
| `src/style.css`、`src/shop.css` | 基础样式、表格和状态徽标，以及导航、选购布局和弹窗样式。 | 两页共用按钮、表格和缺货标记。选购页的弹窗和布局可以集中找。 |
| `src/money.mjs` | 集中处理发布表单的元转分。 | 表单和测试导入同一个函数，测试结果能反映实际提交的金额。 |
| `tests/money.test.mjs` | 用 Node.js 自带的测试运行器验证五组有效金额和四组无效输入。 | 不用启动网页或 Mock，就能检查整数分换算和非法价格。 |

如果继续加退款和优惠券，`shop.js` 会最先变得难改。目前它既负责显示订单，也管理下单和支付。退款会再引入一套订单状态变化，优惠券会改变金额计算。届时我会先把支付流程和金额函数从页面事件里拆出来，再给退款留独立入口。元转分已经从商品管理页拆出，后面可以继续整理两页的金额展示。


## 4. 一次完整链路是怎么走的

我选的是从下单到支付这一条，因为能同时看到库存、订单和支付状态怎么变。

    打开商品选购页 → 点「购买」→ 输入 2 件
      → 前端用整数分算预估价，例如 4990 × 2 = 9980 分，显示 ¥99.80
      → 点「确认下单」，按钮禁用并显示「提交中…」
      → POST /api/orders，quantity 传数字 2
          → 失败：弹窗显示接口原因，恢复提交按钮
          → 成功：显示订单号和实际金额，刷新库存及订单记录
      → 在新订单点「去支付」，选支付宝或微信
      → 点「开始模拟支付」，POST /api/payments，拿到 paymentId
      → 约每秒 GET /api/payments/{paymentId}
          → processing：界面继续显示「支付中…」
          → paid：提示成功，订单显示「已支付」，支付按钮保持禁用
          → 关闭弹窗、离开页面或达到查询上限：停止轮询

页面已经显示「已支付」时，点击按钮所在区域只弹出提示，不会发新请求。如果页面还显示「待支付」，而另一处已经付完，后端返回 `40903` 时会用同一个弹窗显示后端原文。

## 5. 一个取舍：我选了 A，没选 B

- **两个方案**：在原有管理页加购买和订单区 / 分成商品管理页和商品选购页。
- **我选了**：保留 `index.html` 做商品管理，增加 `shop.html` 做商品选购，两页用顶部导航互相跳转。
- **因为**：管理页本来已有分类、列表和发布表单。选购页需要下单后的库存反馈和订单记录。混在一起不好排版且太过混乱，不好操作。拆开后，发布商品时能集中在管理操作，购买后也能直接在选购页看到订单。
- **代价**：两页都需要读取商品数据，切换页面时要重新获取最新库存。目前两个脚本也各有请求和金额格式化代码。再加页面时，可以把这些共用逻辑抽到同一个模块。

## 6. 我卡得最久的一个问题

- **现象**：我在 XYtoken 控制台建好了 API Key，也能打开使用指南，但调用模型接口时，有时提示找不到域名，有时 HTTPS 握手失败。控制台没有看到成功调用的记录。
- **我一开始以为**：可能是 Git Bash 命令写错了，或者模型名的大小写和作业要求不一致。
- **试过什么**：按手册重新核对了接入地址，分别用 Git Bash、PowerShell 和 Node.js 测试。后来改测 `/v1/models`，把模型名和提示词从排查里去掉，也用校园网、手机热点和代理做过对照。在答疑区也询问了老师，进行了处理。
- **最后靠什么缩小范围**：不带 Key 的连接测试也失败，说明当时还没有收到平台的 HTTP 响应，无法验证 Key 或模型名。开代理时，`ping` 能收到回复，但域名解析到了 `198.18.0.7`。这很可能是代理返回的虚拟 IP，所以 ping 通了也不能证明 API 网关能访问。问了老师后用了cc-switch并进行配置，然后测试发现没有权限。
- **目前的结论**：若是用控制台进行连接确认问题卡在域名解析或 HTTPS 连接阶段，具体原因还没有定位。我按老师的要求进行了API接入，仍不能使用，所以先用自己的AI完成前端功能，并在 `AI_USAGE.md` 里如实记录平台接入和实际调用情况。

## 8. 如果还有一天

1. **先补完整的浏览器验收记录。** 支付关闭后停止轮询、跨标签页重复支付、快速连点和下单失败重试都需要用 Network 对照。先做这个，因为界面看起来正常，也可能在后台多发了请求。
