## 测试 / 自检

在服务运行状态下，从仓库根目录执行：

```bash
cd testing/自动化 && pytest -q
```

真实输出：

```text
.....xxx..............xxxxxxxxxx......xxxx........xx..............xxxx   [100%]
47 passed, 23 xfailed, 1 warning in 6.85s
```

- **47 passed**：符合接口文档承诺的正常与异常用例。
- **23 xfailed**：因 SUT 真实缺陷而失败，每条 `reason` 都标注了 BUG 编号。
- 想看到真实的 23 个失败，加 `--runxfail`：`pytest -q --runxfail` → `23 failed, 47 passed`。

`xfail` 全部用了 `strict=True`。这意味着 **SUT 修好之后，对应用例会变成 XPASS 并让 pytest 报错**，强迫同步更新缺陷报告——不会出现"缺陷修了，测试还挂着跳过"的情况。

并发专项单独跑：

```bash
python testing/自动化/concurrency_report.py
```

```text
商品 id=5 初始库存：1
第 1 轮：成功下单 7　409 拒绝 3　库存 1 -> -6
...
[结论] 存在超卖：库存被扣成负数，最小 -6。对应 BUG-12。
```

换端口执行（fixture 支持）：

```bash

```
