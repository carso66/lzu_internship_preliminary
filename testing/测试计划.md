# CampusMall 自动化测试计划

## 1. 测试目标

对 CampusMall 系统开展接口功能、业务边界、安全性及并发场景测试，验证系统在正常输入、异常输入及恶意请求下的响应行为，识别潜在业务和安全缺陷。

## 2. 测试范围

| 测试模块 | 测试内容 |
|---|---|
| 用户认证 | 登录、登出、Token有效性 |
| 权限控制 | 用户资料、订单、管理员接口访问权限 |
| 商品管理 | 商品查询、详情、状态修改、价格边界 |
| 订单管理 | 下单、金额计算、数量校验、库存管理 |
| 支付管理 | 支付创建、支付归属、回调验证、重复请求 |
| 并发测试 | 多请求同时购买最后一件商品 |
| 输入安全 | SQL注入、非法参数 |
| 输出安全 | XSS内容转义 |
| 日志安全 | 密码及Token泄露检查 |
| Token安全 | 伪造Token及身份冒充 |

## 3. 测试环境

- 操作系统：Windows
- Python：3.10.22
- pytest：9.2.0
- HTTP测试工具：requests
- 数据库：SQLite
- 测试框架：pytest
- 被测程序：testing/sut/app.py

## 4. 测试方法

1. 使用接口请求验证正常业务流程。
2. 通过非法参数和边界值验证输入处理。
3. 通过不同用户身份验证资源访问控制。
4. 通过恶意输入验证SQL注入和XSS防护。
5. 通过多线程请求验证库存并发控制。
6. 通过数据库状态检查确认接口操作是否真正改变数据。
7. 通过日志检查验证敏感信息保护情况。

## 5. 测试数据与隔离

测试通过pytest fixture启动独立的被测服务，并为每个测试用例创建临时SQLite数据库。测试结束后关闭服务，避免修改原始测试数据库。

## 6. 测试执行与判定

每个测试用例根据预期HTTP状态码、响应内容和数据库状态进行判定。

- PASS：实际行为符合预期。
- FAIL：实际行为不符合预期。
- ERROR：测试执行过程中发生异常。
- SKIPPED：测试被主动跳过。

安全测试中，FAIL可能意味着被测系统存在漏洞，并不等同于自动化测试框架运行失败。

## 7. 测试退出标准

完成既定测试范围，形成测试结果记录、缺陷清单及代码审查报告。对于未通过的安全用例，应保留复现证据，并明确区分已验证缺陷和待进一步确认的问题。
