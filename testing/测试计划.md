# 测试计划

> 被测对象：校园好物市集（`testing/sut/app.py`，Python 标准库单文件服务，SQLite 落库）
> 作业方向：测试 / 质量保障　│　执行人：袁楚雅 220250946990

## 1. 测什么

覆盖 SUT 全部 **16 个接口**，按五个业务模块 + 一个运维接口划分：

| 模块 | 接口 | 测试方面 |
|---|---|---|
| 认证 | `POST /api/auth/login`、`POST /api/auth/logout` | 正常登录、错误口令、token 有效性与可撤销性、token 可预测性 |
| 用户 | `GET /api/users/{id}` | 正常读取、**横向越权**（读他人资料）、不存在 ID |
| 商品 | `GET /api/products`、`GET /api/products/{id}`、`POST /api/products`、`PATCH /api/products/{id}/status` | 列表分页与筛选、**SQL 注入**、`pageSize` 边界、路径参数类型、发布校验、**纵向越权**（改他人商品） |
| 订单 | `POST /api/orders`、`GET /api/orders/{id}`、`GET /api/orders/mine`、`GET /api/admin/orders` | **金额篡改**、`quantity` 边界与负值、库存扣减正确性、**并发超卖**、下架商品可售性、订单归属、管理端角色校验 |
| 支付 | `POST /api/payments`、`POST /api/payments/callback` | **重复支付**、订单归属与存在性、**回调伪造**、金额一致性 |
| 评价 | `GET /api/product-reviews`、`POST /api/product-reviews` | 内容长度边界、评分边界、**HTML 转义（存储型 XSS）** |
| 运维 | `GET /health` | 存活探针 |

测试类型分布：**功能正常 / 异常参数 / 边界值 / 权限 / 安全 / 幂等 / 并发**七类。

## 2. 哪些暂不测，为什么

| 不测内容 | 原因 |
|---|---|
| 性能与压测（TPS、P95 延迟） | 题目未要求，SUT 为单机 SQLite 且下单路径内嵌 150ms 等库存窗口，压测数据无参考价值 |
| 前端页面渲染 / 浏览器兼容 | `/api/product-reviews` 是唯一服务端渲染页，只作为 XSS 验证载体，不做 UI 兼容性测试 |
| 数据库层故障注入（磁盘满、连接池耗尽） | 需要改造 SUT，题目明确"别改 `sut/`" |
| 短信 / 真实支付网关对接 | SUT 内支付为模拟实现，无外部依赖 |
| 长时间稳定性（7×24 运行） | 48 小时作业周期内无法观察 |

## 3. 方法与工具

| 用途 | 工具 |
|---|---|
| 手工探索与证据留存 | `curl`（每条缺陷都附可直接复制执行的命令 + 真实返回） |
| 自动化回归 | `pytest` + `requests`，脚本置于 `testing/自动化/`，`conftest.py` 统一管理 `base_url` 与 token fixture |
| 并发验证 | Python `threading.Barrier` 让 10 个请求同时发出，避免"伪并发" |
| 源码辅助定位 | 允许看源码，但**结论必须由运行证据支撑**；仅凭源码推测的条目不写进缺陷报告 |
| 数据复位 | 每条缺陷采集前重启 SUT（启动时自动重建库并写种子数据），保证他人可复现 |

## 4. 结束条件

满足以下全部条件即结束本轮：

1. 16 个接口**每个至少 1 条**用例执行完毕，且正常路径全部通过（避免误报）。
2. 正常 / 异常 / 边界三类用例各 ≥3 条，用例总数 ≥15 条。
3. 缺陷数 ≥4 条且**每条都有可执行的 curl 与真实返回**；实际做到 17 条。
4. 并发与幂等两类"必须动手跑"的场景各完成至少 1 次实测（并发超卖、重复支付、回调伪造）。
5. `cd testing/自动化 && pytest -q` 能在服务运行时跑完，失败项均能对应到缺陷编号。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 缺陷之间相互污染数据（如 `quantity=-5` 会把库存越测越多） | 每条缺陷前重启服务，回到种子状态 |
| 把 SUT 缺陷误判成脚本 bug | 每条自动化用例先用 curl 手工确认一遍，再固化为脚本；脚本失败必须能在缺陷报告中找到编号 |
| 并发测试偶发不超卖（时序碰巧） | 用 `Barrier` 对齐起跑点，重复跑 3 轮，取最差结果记录 |
