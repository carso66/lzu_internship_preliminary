# CampusMall 自动化测试报告

## 1. 测试概况

本次测试针对CampusMall系统开展接口功能、业务边界、安全性及并发测试，采用pytest和requests构建自动化测试环境。

测试通过独立临时SQLite数据库隔离测试数据，避免修改原始数据库。

## 2. 测试环境

| 项目 | 配置 |
|---|---|
| 操作系统 | Windows |
| Python | 3.10.22 |
| pytest | 9.2.0 |
| HTTP工具 | requests |
| 数据库 | SQLite |
| 测试框架 | pytest |

## 3. 测试执行结果

本次完整测试执行命令：

`python -m pytest testing\自动化 -v --tb=short --junitxml=testing\自动化\reports\submission-final.xml`

测试结果：

| 指标 | 数量 |
|---|---:|
| 总用例数 | 46 |
| 通过 | 13 |
| 未通过 | 33 |
| 执行错误 | 0 |
| 跳过 | 0 |
| 通过率 | 28.26% |

说明：安全测试的失败可能意味着被测系统未满足安全预期，因此不能简单将所有失败解释为测试程序错误。需要结合实际响应及数据库证据判断。

## 4. 主要测试发现

### 4.1 用户权限控制

发现普通用户访问其他用户资料、订单及管理员接口的权限控制存在问题。

### 4.2 商品管理

发现普通用户可能修改其他卖家的商品状态；商品分页参数及非数字商品ID的异常处理不完善。

### 4.3 订单管理

发现服务端可能信任客户端提交的价格，购买数量缺少充分校验，并发购买场景存在超卖风险。

### 4.4 支付管理

发现支付回调真实性校验、支付记录绑定及重复请求处理需要进一步验证。

### 4.5 输入安全

发现商品搜索接口对特殊输入的处理存在异常，需进一步检查SQL查询条件及参数化处理。

### 4.6 其他安全问题

对Token伪造、XSS输出转义和敏感日志泄露开展了自动化检查，相关未通过项目应结合单项测试证据进一步确认。

## 6. 测试结论

本次已建立覆盖认证、权限、商品、订单、支付、并发及输入安全等方面的自动化测试体系。

当前被测系统仍存在未通过的安全及业务测试项目，尚不能认定全部测试要求已经满足。

本次测试报告保留实际执行结果，不将未通过项目人为修改为通过。
