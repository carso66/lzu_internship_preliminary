## BUG-01 会话 token 可预测且登出后仍有效

- **模块**：认证
- **严重程度**：S1
- **发现 / 覆盖用例**：TC-004、STC-002
- **前置条件**：SUT 已启动，alice 已登录，token 为 `tk_2`
- **复现步骤**：
  1. 登出 alice。
  2. 继续用原 token 访问用户详情。
  3. 不登录，直接使用可预测 token `tk_2` 访问用户详情。
- **预期结果**：登出后原 token 返回 `401`；仅凭可预测 token 不应通过认证。
- **实际结果**：两种方式均返回 `200`，并返回 alice 的真实姓名和手机号。
- **证据**：
  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/auth/logout \
    -H 'Authorization: Bearer tk_2'

  curl -s http://127.0.0.1:18081/api/users/2 \
    -H 'Authorization: Bearer tk_2'
  ```
  ```json
  {"code":0,"message":"ok","data":{"message":"已退出登录"}}

  {"code":0,"message":"ok","data":{"id":2,"username":"alice","realName":"张爱丽","phone":"13800138002","role":"user"}}
  ```
- **影响**：token 可被猜测，且登出不生效，存在账户接管风险。
- **修复建议**：使用随机不可预测 token；服务端保存会话状态；登出时删除或失效对应会话；校验有效期。

## BUG-02 用户资料接口存在水平越权

- **模块**：用户权限
- **严重程度**：S1
- **发现 / 覆盖用例**：TC-007、STC-003
- **前置条件**：alice 已登录，token 为 `tk_2`
- **复现步骤**：alice 访问 bob 的用户详情。
- **预期结果**：`403`，不能返回他人资料。
- **实际结果**：`200`，返回 bob 的真实姓名和手机号。
- **证据**：
  ```bash
  curl -s http://127.0.0.1:18081/api/users/3 \
    -H 'Authorization: Bearer tk_2'
  ```
  ```json
  {"code":0,"message":"ok","data":{"id":3,"username":"bob","realName":"李波","phone":"13800138003","role":"user"}}
  ```
- **影响**：登录用户可枚举他人手机号和姓名。
- **修复建议**：在用户详情处理逻辑中比较当前用户 ID 与路径 ID，不一致时返回 `403`。

## BUG-04 商品列表 `pageSize` 未做范围校验

- **模块**：商品
- **严重程度**：S3
- **发现 / 覆盖用例**：TC-012
- **前置条件**：SUT 已启动
- **复现步骤**：请求 `pageSize=51`。
- **预期结果**：`400`，`pageSize` 范围应为 `1~50`。
- **实际结果**：`200`，返回 `pageSize=51`。
- **证据**：
  ```bash
  curl -s 'http://127.0.0.1:18081/api/products?page=1&pageSize=51'
  ```
  ```json
  {"code":0,"message":"ok","data":{"total":11,"page":1,"pageSize":51,"items":[...]}}
  ```
- **影响**：分页约束失效，可能导致异常大查询或客户端误解。
- **修复建议**：校验 `pageSize` 为 `1~50` 的整数，越界返回 `400`。

## BUG-06 商品列表 `keyword` 存在 SQL 注入

- **严重程度**：S1
- **发现 / 覆盖用例**：STC-005
- **前置条件**：SUT 已启动

## BUG-08 下单接口缺少关键业务校验

- **模块**：订单
- **严重程度**：S1
- **发现 / 覆盖用例**：TC-019、TC-022、STC-006、STC-009
- **前置条件**：alice 已登录，token 为 `tk_2`
- **复现步骤**：
  1. 提交 `quantity=0`。
  2. 提交被篡改的 `unitPrice` 和 `totalAmount`。
  3. 对已下架商品 `id=7` 下单。
- **预期结果**：
  - `quantity=0` 应返回 `400`；
  - 服务端应忽略客户端金额，按商品价格计算；
  - 下架商品应返回 `409`。
- **实际结果**：三种请求均返回 `201`，分别生成数量为 0、金额为 1、下架商品订单。
- **证据**：
  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/orders \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"productId":1,"quantity":0}'

  curl -s -X POST http://127.0.0.1:18081/api/orders \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"productId":1,"quantity":2,"unitPrice":1,"totalAmount":1}'

  curl -s -X POST http://127.0.0.1:18081/api/orders \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"productId":7,"quantity":1}'
  ```
  ```json
  {"code":0,"message":"ok","data":{"id":3,"quantity":0,"totalAmount":0.0}}

  {"code":0,"message":"ok","data":{"id":4,"unitPrice":1,"totalAmount":1}}

  {"code":0,"message":"ok","data":{"id":5,"productId":7,"totalAmount":6880.0}}
  ```
- **影响**：可创建异常订单、篡改支付金额并购买不可售商品。
- **修复建议**：强制校验数量为正整数；金额只能由服务端按商品价格和数量计算；下单前校验商品状态为 `on`。

## BUG-10 支付流程缺少完整性校验

- **模块**：支付
- **严重程度**：S1
- **发现 / 覆盖用例**：TC-026、TC-027、CTC-003、CTC-004
- **前置条件**：alice / bob 已登录，订单 `id=1` 属于 alice
- **复现步骤**：
  1. 支付不存在订单 `999999`。
  2. 对订单 `1` 连续支付两次。
  3. bob 支付 alice 的订单 `1`。
- **预期结果**：
  - 不存在订单应返回 `404`；
  - 重复支付应返回 `409`；
  - 支付他人订单应返回 `403`。
- **实际结果**：三种请求均返回 `200`，并生成支付记录。
- **证据**：
  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/payments \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"orderId":999999,"method":"alipay"}'

  curl -s -X POST http://127.0.0.1:18081/api/payments \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"orderId":1,"method":"alipay"}'

  curl -s -X POST http://127.0.0.1:18081/api/payments \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_3' \
    -d '{"orderId":1,"method":"alipay"}'
  ```
  ```json
  {"code":0,"message":"ok","data":{"orderId":999999,"amount":0,"status":"paid"}}

  {"code":0,"message":"ok","data":{"orderId":1,"amount":3980,"status":"paid"}}

  {"code":0,"message":"ok","data":{"orderId":1,"amount":3980,"status":"paid"}}
  ```

## BUG-11 支付回调未验签

- **模块**：支付
- **严重程度**：S1
- **发现 / 覆盖用例**：STC-007、STC-011、CTC-004
- **前置条件**：SUT 已启动，存在订单
- **复现步骤**：
  1. 提交无签名的支付回调。
  2. 对不存在订单提交回调。
- **预期结果**：无有效签名或订单不存在时应拒绝，不能将订单标记为 `paid`。
- **实际结果**：两种请求均返回 `200`，订单状态被置为 `paid`。
- **证据**：
  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/payments/callback \
    -H 'Content-Type: application/json' \
    -d '{"orderId":2,"paymentId":"PAY202609200001","result":"success"}'

  curl -s -X POST http://127.0.0.1:18081/api/payments/callback \
    -H 'Content-Type: application/json' \
    -d '{"orderId":999999,"paymentId":"PAY202609200001","result":"success"}'
  ```
  ```json
  {"code":0,"message":"ok","data":{"orderId":2,"status":"paid"}}

  {"code":0,"message":"ok","data":{"orderId":999999,"status":"paid"}}
  ```

  **paymentId 不匹配补充证据：**

  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/payments/callback \
    -H 'Content-Type: application/json' \
    -d '{"orderId":2,"paymentId":"PAY202609999999","result":"success"}'
  ```
  ```json
  {"code":0,"message":"ok","data":{"orderId":2,"status":"paid"}}
  ```
- **影响**：外部请求可伪造支付成功，造成订单状态篡改。
- **修复建议**：回调必须验签、校验 paymentId 与订单匹配，并校验订单存在；验签失败返回 `401` 或 `403`。

## BUG-13 订单金额计算存在浮点精度误差

- **模块**：订单
- **严重程度**：S2
- **发现 / 覆盖用例**：TC-018
- **前置条件**：SUT 已重启并重建种子数据，alice 已登录
- **复现步骤**：对商品 `id=1` 下单，数量为 `2`。
- **预期结果**：`totalAmount` 精确等于 `3980`。
- **实际结果**：返回 `201`，但 `totalAmount` 为 `3979.9999999999995`。
- **证据**：
  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/orders \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"productId":1,"quantity":2}'
  ```
  ```json
  {"code":0,"message":"ok","data":{"id":3,"orderNo":"SO202611240003","productId":1,"productTitle":"无线蓝牙耳机","quantity":2,"unitPrice":1990,"totalAmount":3979.9999999999995,"status":"created"}}
  ```
- **影响**：金额计算结果不是精确整数，可能影响展示、对账、支付和后续统计。
- **修复建议**：订单金额统一以“分”为整数计算，避免使用浮点数；计算后再转换为展示金额。

## BUG-14 并发购买导致库存超卖

- **模块**：订单
- **严重程度**：S1
- **发现 / 覆盖用例**：CTC-002
- **前置条件**：SUT 已重启并恢复初始数据，商品 `id=5` 库存为 `1`
- **复现步骤**：
  1. 向商品 `id=5` 发起 10 个并发购买请求，每个请求数量为 `1`。
  2. 统计返回 `201` 的订单数。
  3. 查询商品 `id=5` 的最终库存。
- **预期结果**：最多 1 个订单创建成功，最终库存为 `0`。
- **实际结果**：10 个订单均创建成功，最终库存为 `-9`。
- **证据**：

  ```bash
    -X POST http://127.0.0.1:18081/api/orders \
    -H 'Content-Type: application/json' \
    -H 'Authorization: Bearer tk_2' \
    -d '{"productId":5,"quantity":1}'

  curl -s http://127.0.0.1:18081/api/products/5
  ```
  ```text
  201
  201
  201
  201
  201
  201
  201
  201
  201
  201

  {"code":0,"message":"ok","data":{"id":5,"title":"轻薄防晒外套","price":8990,"stock":-9,"status":"on"}}
  ```

  也可用自动化测试复现：

## BUG-15 登录日志输出明文密码

- **模块**：认证
- **严重程度**：S2
- **发现 / 覆盖用例**：STC-012
- **复现步骤**：
  1. 启动 SUT。
  2. 使用 alice 正常登录。
  3. 查看服务端控制台日志。
- **预期结果**：日志不得输出明文密码。
- **实际结果**：日志直接输出明文密码。
- **证据**：
  ```bash
  curl -s -X POST http://127.0.0.1:18081/api/auth/login \
    -H 'Content-Type: application/json' \
    -d '{"username":"alice","password":"Alice@123"}'
  ```
  ```text
  2026-11-24 22:43:00 [auth] 登录请求 username=alice password=Alice@123
  ```
- **影响**：日志泄露登录凭证，可能导致账号被盗用。
- **修复建议**：删除日志中的密码字段，必要时只记录脱敏后的凭据标识。
