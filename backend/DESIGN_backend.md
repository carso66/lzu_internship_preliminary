# 后端设计说明（开发中）

## 当前范围与开发顺序

先完成健康检查，确认 Java、Maven 和 HTTP 服务能运行；再建表并验证约束，
为后续商品接口和下单事务准备基础。业务接口将在后续步骤逐项实现。

## 表结构与约束

- `products` 保存商品信息。价格为整数分，使用 BIGINT；库存为非负 INTEGER。
- `orders` 保存订单。商品 ID 外键关联商品，订单号设置唯一约束。
- 商品标题和成交单价在订单内留存快照，后续商品信息变化不会改变历史订单。
- 订单数量至少为 1；商品状态限定为 on/off，订单状态限定为 created/paid。
- 本项目自行选择正整数价格规则；标题最多 120 字符、分类 60 字符、
  商品描述 2000 字符、姓名 60 字符、收货地址 500 字符。
- 时间使用 TIMESTAMP，创建时间由数据库提供默认值。
- 数据库约束作为最后一道防线；后续接口还需提前校验并转换为题目规定的业务错误。

## 数据库初始化链路

```text
Maven 复制 backend/schema.sql 到 classpath
  → Spring Boot 创建 H2 DataSource
  → 执行建表 SQL
  → 建表成功后启动服务；SQL 错误时启动失败
```

## 技术取舍

选择 H2 内存数据库，便于评审一条命令启动，且每次运行从空数据开始。
代价是应用进程重启会丢失数据。后续如需持久化，可替换数据库连接并调整初始化策略。
使用 JDBC 执行显式 SQL，便于说明之后的库存扣减与事务边界。

## 验证与后续工作

通过真实 Spring Boot 上下文连接 H2，验证建表、BIGINT 金额、快照、唯一约束和 CHECK 约束。
测试方法通过事务回滚隔离数据；不向开发数据库插入测试样本。

## 商品发布的模块与流程

- `ProductController` 接收 HTTP 请求，返回 201 和统一响应。
- `CreateProductRequest` 声明必填、长度和数值范围规则；`JacksonConfiguration` 禁止字符串、
  小数等自动转换为整数，避免客户端传错类型后被静默接受。
- `ProductService` 提供创建商品的事务边界。
- `ProductRepository` 通过绑定参数插入商品，读取数据库生成的 ID、创建时间等字段。
- `ApiExceptionHandler` 把字段和 JSON 错误转换为 400/40001；未知内部异常只在服务端记录。

```text
POST /api/products
  → JSON 类型检查和字段校验
  → 开启事务，插入商品并读取入库结果
  → 返回 201 + 商品信息
  → 类型/范围/长度错误返回 400，且不插入商品
```

商品初始状态由服务端设为 on；空缺描述保存为空字符串。查询 SQL 使用绑定参数，
不拼接用户输入。金额使用 long/BIGINT；发布测试覆盖超过 32 位整数范围的价格。
