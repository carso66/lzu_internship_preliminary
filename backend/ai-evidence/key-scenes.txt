## 1. 库存使用条件更新，而不是“先查再无条件减”

```sql
UPDATE products
SET stock = stock - ?
WHERE id = ?
  AND stock >= ?
```

这是正确且重要的设计。

它把“检查库存”和“扣库存”合成一条原子 SQL：

- 库存足够：更新成功，影响 1 行；
- 库存不足：更新 0 行；
- 并发请求时，数据库会保证不会因为多个请求同时读到相同库存而超卖。

**不要改回以下形式：**

```sql
SELECT stock FROM products WHERE id = ?;
-- Java 判断库存
UPDATE products SET stock = stock - ? WHERE id = ?;
```

先查询再更新会产生竞态条件。

## 结论

你的现有处理逻辑只需要修改 **`GlobalExceptionHandler`**，不需要修改 Controller、DTO、Service 或 Repository。

Jackson 3.1.8 中，字段路径信息位于：

```java
tools.jackson.databind.JsonMappingException#getPath()
```

路径中的引用对象支持：

```java
reference.getFieldName()
```

注意 Jackson 3 的包名是：

```java
tools.jackson.databind.JsonMappingException
```

不再是 Jackson 2 的：

```java
com.fasterxml.jackson.databind.JsonMappingException
```

## 一、Jackson 3 异常链

字段类型不匹配时，Spring 的异常链通常类似：

```text
HttpMessageNotReadableException
└── MismatchedInputException
    └── InvalidFormatException / JacksonException
```

其中：

- `MismatchedInputException`：处理 `"stock": "10"` 一类的字段类型不匹配；
- `InvalidFormatException`：处理 `"price": 19.9` 一类的数字格式不匹配；
- 它们都继承自 `JsonMappingException`；
- `JsonMappingException#getPath()` 保存字段路径。

JSON 语法损坏时，异常链通常是：

```text
HttpMessageNotReadableException
└── StreamReadException
```

它不是字段映射异常，通常没有可用的字段路径，因此应该保留通用提示。
