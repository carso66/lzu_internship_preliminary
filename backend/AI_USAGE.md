### 场景 1：做商品列表筛选和分页

- **我想干什么**　让商品列表支持关键词、状态和分类组合筛选，并返回总数和当前页。

- **我怎么问的**　待按平台记录补充原提问。这个任务涉及三个筛选条件、分页和非法参数的返回值。
- **它给了什么**　本次可核对的实现是商品列表接口、MyBatis 查询和对应的接口测试，见提交 `b378064`。具体哪段是模型原始输出，需对照平台记录。
- **我改了吗、为什么改**　最后的代码同时覆盖了默认分页、无匹配结果、超大页码和非法参数。改动归属以当时的对话为准。
- **怎么确认改对了**　用 `ProductListApiTest` 检查默认分页、组合筛选、空结果和非法参数。
- **结论**　筛选和分页实现进入了提交，接口行为由测试确认。

### 场景 2：处理本地 JDK 19 和评审 JDK 17 的差异

- **我想干什么**　确认评审只有 JDK 17 时能否构建和启动项目。
- **用的模型 / 为什么选它**　本次使用了有本地终端的编码助手，因为需要读取 POM、执行 Maven 并检查生成的字节码。
- **我怎么问的**　我本地用 JDK 19，评审可能用 JDK 17，怎么协调？
- **它给了什么**　检查到 POM 的原始目标是 Java 19，建议把目标改为 Java 17 并配置 `maven.compiler.release`。
- **我改了吗、为什么改**　采用了编译目标修改，见提交 `7adc597`。后来我要求安装 JDK 17，用真实运行环境确认兼容性。
- **怎么确认改对了**　先用 JDK 19 构建并检查 `.class` 的版本，再用 JDK 17 执行 `mvn clean package`。76 项测试全部通过，健康检查返回 HTTP 200。
- **结论**　采用 Java 17 编译目标，并通过 JDK 17 实测验证。

### 场景 3：追问金额为什么用整数分

- **我想干什么**　把设计说明里的金额取舍写清楚，说明整数分和 `BigDecimal` 各自适合什么场景。
- **用的模型 / 为什么选它**　本次使用了能读取题目和本地代码的编码助手，方便核对接口约定与实际算价方式。
- **我怎么问的**　`BigDecimal` 更灵活，这个项目为什么选整数分？
- **它给了什么**　结合题目和代码说明，接口要求整数分，总额只需要用分为单位的单价乘整数件数。
- **我改了吗、为什么改**　我要求把原因写具体。最后补上了接口、Java 计算和数据库统一用分的好处，也写明折扣、计税或分摊出现不足一分的中间值时，`BigDecimal` 更灵活。
- **怎么确认改对了**　对照题目里的金额约定、`schema.sql` 的 `BIGINT` 字段以及 `OrderService` 中的 `Math.multiplyExact`。文档修改见提交 `7ef54c7`。
- **结论**　保留整数分，修改了最初过于笼统的解释。

## 4. 一次被 AI 带偏的经历（必答）

- **它给了什么**　AI 写了一个空缓存验证脚本，只把 `pom.xml` 和 `src` 复制到临时目录，遗漏了 `backend/schema.sql`。
- **当时为什么信了**　当时直接用 AI 准备的临时目录跑启动检查，直到启动报错才检查副本里有哪些文件。
- **我怎么发现的**　依赖下载后，Spring Boot 在数据库初始化时报 `No schema scripts found at location 'classpath:schema.sql'`。对照 POM 的资源配置，发现 `schema.sql` 放在 `backend` 根目录。
- **最后怎么修的**　补齐建表脚本后重跑启动，再给项目指定另一个空 Maven 仓库执行打包。测试全部通过，启动后健康检查返回 HTTP 200。
- **之后我改了做法吗**　这次补齐了启动所需的建表脚本，并分别核对打包、启动和健康检查的结果。
