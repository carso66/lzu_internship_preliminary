## 3. 挑 4 个场景写下来（5 分）



### 场景 1：根据需求去按照TDD模式生成测试然后编码

- **我想干什么**　让商品列表支持关键词、状态和分类组合筛选，并返回总数和当前页。
- **用的模型 / 为什么选它**　DeepSeek-V4.1-Flash，这类任务有明确的接口行为，可逐项写测试然后验收。
- **我怎么问的**　根据需求文档，使用TDD Skills 编码。
- **它给了什么**　对应的接口测试，以及编码实现，最终确定测试能过。
- **我改了吗、为什么改**　没改。
- **怎么确认改对了**　审查模型生成的测试是否覆盖全面 ，审查测试是否全过 ，用另一个模型review没问题。

### 场景 2：用 grill-me 和 AI 讨论下单并发

- **我想干什么**　确定下单怎么防超卖，以及插入订单失败时怎么回滚库存。
- **用的模型 / 为什么选它**　DeepSeek-V4.1-Flash，便宜，性价比高。
- **我怎么问的**　用 grill me skills 和AI讨论 ，下单接口有哪些并发风险，怎么防超卖？
- **它给了什么**　建议用条件 UPDATE 检查上架状态和库存，并在同一事务里扣库存、写订单。
- **我改了吗、为什么改**　它考虑到了前端连点/超时的情况，让前端传个幂等键，但是题目中的请求没有这个幂等键，最终我让它保留原请求格式，这次只解决库存超卖。
- **怎么确认改对了**　库存为 1 时并发发 10 个请求，1 个成功、9 个返回 409，最终库存为 0、只新增 1 单。另测了插单失败时库存会回滚。

### 场景 3：用 AI 做商品发布接口的 Code Review

- **我想干什么**　检查 L0-2 商品发布接口是否符合题目要求，找出测试没覆盖的情况。
- **用的模型 / 为什么选它**　Kimi-K3.1-Pro，审核任务需要智力比较高的模型做全局把控。
- **我怎么问的**　用 code-review skills 审一下 L0-2 的开发改动。
- **它给了什么**　指出数据库写入异常可能走 Spring Boot 默认响应，导致接口返回的 JSON 不符合题目约定。
- **我改了吗、为什么改**　确认问题后加了统一异常处理，返回 HTTP 500 和业务码 50000。
- **怎么确认改对了**　先模拟写库失败，让新增测试复现问题。

## 5. 成本（4 分）

| 问题 | 我的回答 |
|---|---|
| 有没有“一次把整个项目/整个文件塞进去”？为什么？ | 修bug的时候可以@固定文件。 编码的时候就不好限制了，因为总归是要跨多个文件编码的，但是可以把项目结构写到AGENTS.MD里面，从而限制模型读取文件的数量。 |
