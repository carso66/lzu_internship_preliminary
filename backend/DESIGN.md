## 3. 我的程序分成哪几块

| 文件 / 模块       | 负责什么                  | 为什么单独拆出来                                           |
|---------------|-----------------------|----------------------------------------------------|
| `controller/` | 接收参数 调用service层 返回响应体 | 负责和前端交互，三层负责不同的功能，便于修改 修改返回格式不会影响其他层的代码            |
| `service/`    | 业务逻辑处理（如商品是否下架）管理事务   | 修改业务逻辑和事务，只需要改这一层，事务注解如果放在 controller 里，一次请求会变成多个事务，扣了库存但插单失败时无法回滚 |
| `mapper/`     | SQL语句                 | 更换数据库、增加索引、修改查询条件时，只需要改这一层                         |
| `pojo/`       | 实体类                   | 单独放请求和响应对象，表结构变了修改时只需改一个类，不用改Mapper的SQL和其他代码 |
| `common/`     | 异常处理 统一响应体 JSON 类型校验 业务异常 | 所有功能都要共用的代码模块，不拆出来共用的话每个功能都要重复写                    |

> **抽象能力主要看这一节。** 如果你只写了一个大文件，也如实写，然后回答：**再加"退款"和"优惠券"，哪里会最先乱掉？**

加"退款"和"优惠券"时，最先乱的是 service层：现在OrderService管着 校验、计价、扣库存、生成单号、落订单，
实现退款和优惠券就要把库存加回去、把订单状态改成已退款、生成退款单号、以及部分退款， 加优惠券要在"计价"时判断"券是否能用""能减多少"，
orders 表还要多存一个优惠金额，这些改动主要在在 OrderService 里。

## 4. 一次完整链路是怎么走的

用箭头画一遍。**前端示例（下单）：**

```
用户点"购买" → 弹出数量选择 → quantity=2
  → 校验 quantity 是正整数？ ── ✗ → 红字提示，不发请求
  → POST /api/orders { productId: 3, quantity: 2 }
  → 201 → 用返回的 totalAmount 展示金额 → 重新拉列表，库存变 22
  → 409 "库存不足" → 提示，按钮恢复
```

**后端示例（商品列表）：**

```
GET /api/products?category=文具&page=1
  → 校验筛选和分页参数 → 不合法时返回 400
  → 查符合条件的商品总数、当前页商品
  → 返回列表 → 没有匹配商品时返回空列表
```

**轮到你：** 选你最满意的一条链路画一遍。**画不出说明你自己也没想清，那就是要补的地方。**

POST /api/orders {productId, quantity, buyerName, buyerPhone, address}
→ 校验'quantity'是否是 ≥1 的整数 → 不合法时返回 400+40001
→ 校验buyerName、buyerPhone、address → 不合法时返回 400+40001
→ 校验商品是否存在 → 不存在时返回 404 + 40401「商品不存在」
→ 校验商品是否上架 → 未上架时返回 409 + 40902「商品已下架」
→ 校验商品库存是否充足（stock < quantity） → 不充足时返回 409 + 40901「库存不足」
→ 服务端计价totalAmount
→ 扣库存 → 插订单 → 回查订单 
→ 201 + 订单详情
→ 任何一步抛异常 → 整个事务回滚，已扣的库存还原


## 5. 一个取舍：我选了 A，没选 B

- **可以在哪两个方案里选**：__H2内存库__ / __MySQL__
- **我选了**：__H2内存库__
- **因为**：__虽然我之前用的都是MySQL,但在本次测试中MySQL不利于验收且操作较为复杂，而H2每次启动都是干净数据，且操作简单,便于验收__
- **代价是**：__进程一停数据全丢，每次重启都要重新发布商品，不能像MySQL一样留存数据__

> ✅ 有用：开发时我在内存数据库和本地文件数据库之间选了前者，因为评审每次启动都能从相同的初始数据开始；代价是重启会丢掉我刚创建的商品。
>

## 6. 我卡得最久的一个问题

- **现象**：__刚开始项目时IDE里的'pom.xml'里的依赖全爆红__
  - **我一开始以为**：__SpringBoot 4.0.10版本太新或者IDE设置里的Maven主路径有误__
- **试过什么**：__降低SpringBoot版本 修改IDE设置里的Maven主路径 重新新建项目重新加载__（2~3 个）
- **最后靠什么定位的**：__考虑到可能是依赖没下载下来 查Maven仓库目录发现确实如此__（看报错原文？打日志？F12 Network？二分注释？把代码删到最小复现？）
- **真正的原因**：__Maven主路径确实配置错误，且我 settings.xml 里配的是阿里云镜像的旧址 且原本是 http:// 而不是 https://。
- Maven 3.8.1 之后自带一个 maven-default-http-blocker，把所有 http 仓库都拦截了，所以每次下载都被拒绝 ，
- 只在本地留下一个 .lastUpdated 记录。而 Maven 在 24 小时内不会重试同一个坐标，所以后面无论怎么点刷新都是“立刻失败”。__

> 这一节我们最看重。**不看你会不会，看你遇到不会的时候怎么办。**
