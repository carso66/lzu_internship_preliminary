## 运行

在 Windows 11 x64、Go 1.27.1 上验证过。工程要求 Go 1.23.0 或更高版本。SQLite 驱动通过 Go Modules 下载，首次启动需要联网。无需安装数据库服务或 C 编译器。

从仓库根目录运行：

```sh
cd backend
go run .
```

打开 <http://127.0.0.1:8080/api/health>，响应中的 `code` 应为 0。服务第一次启动时在当前目录创建空的 `market.db`。如需更换库文件或端口，可运行 `go run . -db demo.db -addr 127.0.0.1:8081`。重启时使用同一文件即可读到之前的订单。

## 完成情况

| 层级 | 实现 |
|---|---|
| L0，5 项 | 手写建表 SQL；发布商品；按关键词、分类和状态组合筛选并分页；商品详情；上下架。 |
| L1，全部 | 事务下单、校验参数、按订单号查详情、按买家手机号分页查单。成交单价从数据库读取。 |
| L2，第 9、10 项 | 同步模拟支付，同一订单只能成功一次；10 个请求争抢最后一件商品时只生成一张订单。 |

未选做登录鉴权和索引执行计划对比。支付使用模拟流水，不向支付宝或微信发起扣款。

## 从空库走一单

向下表中的接口发送 JSON 请求。示例中的手机号是测试占位值。成功响应都在 `data` 中给出结果。

| 请求 | 请求体或查询参数 | 验收时看什么 |
|---|---|---|
| `POST /api/products` | `{"title":"素描本","price":1990,"stock":2,"category":"文具","sellerName":"测试店"}` | HTTP 201，记下返回的商品 `id`。 |
| `GET /api/products` | `?keyword=素描&status=on&category=文具&page=1&pageSize=10` | 筛选后的总数及本页商品。 |
| `POST /api/orders` | `{"productId":1,"quantity":2,"buyerName":"测试买家","buyerPhone":"10000000000","address":"测试自提点"}`，将 `1` 换成实际商品编号 | HTTP 201，订单总额为 3980 分，记下 `orderNo`。 |
| `GET /api/products/{id}` | 路径中填实际编号 | 库存由 2 减为 0。 |
| `GET /api/orders` | `?buyerPhone=10000000000&page=1&pageSize=10` | 该买家的订单按创建时间倒序排列。 |
| `POST /api/payments` | `{"orderNo":"返回的订单号","method":"wechat"}` | 第一次成功生成支付流水；同一请求再发一次返回 HTTP 409，业务码 `40903`。 |
| `GET /api/orders/{orderNo}` | 路径中填实际订单号 | 已支付订单的状态为 `paid`，`paidAt` 有值。 |
| `PATCH /api/products/{id}/status` | `{"status":"off"}` | HTTP 200，下架后再下单返回 `40902`。 |

## 自动验收

在 `backend/` 下执行：

```sh
go test -count=1 -v ./...
go vet ./...
```

五个测试分别检查商品组合筛选和翻页、订单计价和查询、订单插入失败后的回滚、并发扣库存、重复支付。测试使用临时库，不读取开发库。

单独复核并发验收可运行 `go test -v -count=20 -run TestConcurrent ./...`。测试自行建库和准备商品，再用同一条通道同时放行 10 个请求。下单测试从库存 1 开始，支付测试先建一张待付款订单。每轮同时核对 HTTP 响应和库内记录。20 轮复测通过，输出中的计数为：

```text
201=1 40901=9 stock=0 orders=1
200=1 40903=9 receipts=1
```

另用独立进程做过重启检查。按 1990 分买两件并支付后，重启服务仍能查到库存 0、订单已支付，重复支付仍返回 `40903`。
