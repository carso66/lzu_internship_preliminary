## L2-10 并发不超卖

**并发控制方案**：下单接口用带条件的 UPDATE 扣库存——
`UPDATE products SET stock = stock - #{quantity} WHERE id = #{id} AND stock >= #{quantity} AND status = 'on'`。
由数据库行锁保证：10 个请求同时到达时，只有一个能把库存从 1 减到 0，其余 9 个因 `stock >= quantity` 不成立而更新 0 行，
接口据此返回 409「库存不足」。扣库存和写订单在同一个 `@Transactional` 里，任何一步失败整体回滚。

**如何准备数据**：不用手动准备。脚本运行时会自动 POST /api/products 新建一个
「上架（status 默认 on）且库存 = 1」的商品，并用唯一 buyerPhone 隔离本轮订单，每次运行互不影响、可重复跑。

**如何运行**（先 `cd backend` 并确认服务已启动）：

```bash
新打开一个控制台（cmd）
cd backend
powershell -ExecutionPolicy Bypass -File .\scripts\concurrency-check.ps1
```

**如何核对**：脚本自动打印 4 项检查，全部 PASS 时退出码为 0，否则为 1：

| 核对项 | 期望值 |
|---|---|
| 恰好 1 个请求返回 201 成功 | 1 |
| 其余 9 个返回 409「库存不足」 | 9 |
| 商品库存 | 0 |
| 本轮新增订单数 | 1 |
